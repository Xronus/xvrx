Окружение: Docker / staging / production (нужное подчеркнуть)

## 1. Подготовка

- [ ] Контейнеры запущены: `docker compose up -d --build`.
- [ ] `docker compose ps` показывает healthy для `mysql`, `app`, `nginx` и `soap-mock`.
- [ ] Открывается <http://localhost:8010/up>.
- [ ] Миграция `add_totp_to_users_table` отмечена как `Ran`.
- [ ] Доступен администратор `admin` / `Admin123!`.
- [ ] Доступен обычный пользователь `test` / `User123!`.
- [ ] На телефоне установлен Google Authenticator, 1Password, Aegis или другой TOTP-клиент.
- [ ] Перед началом 2FA администратора сброшена:

```bash
docker compose exec app php artisan 2fa:reset admin@example.test
```

## 2. Контроль доступа до настройки

- [ ] Войти пользователем `test` и открыть `/powerpuffsiteadmin` — ожидается `403`.
- [ ] Пользователь `test` не видит элементы управления админской 2FA в кабинете.
- [ ] Прямые переходы пользователя `test` на `/cp/2fa/setup`, `/cp/2fa/challenge` и POST-маршруты 2FA отклоняются с `403`.
- [ ] Войти пользователем `admin` без настроенной 2FA.
- [ ] Открыть `/powerpuffsiteadmin` — ожидается редирект на `/cp/2fa/setup`.
- [ ] Обычные страницы кабинета администратора доступны без TOTP challenge.

Фактический результат / замечания:

>

## 3. Настройка TOTP

- [ ] На `/cp/2fa/setup` отображается состояние «2FA не настроена».
- [ ] Нажать «Сгенерировать ключ» — появляется QR-код и ручной секрет.
- [ ] QR-код сканируется TOTP-приложением.
- [ ] Неверный шестизначный код возвращает понятную ошибку и не включает 2FA.
- [ ] Верный код включает 2FA.
- [ ] После подтверждения показываются восемь recovery-кодов.
- [ ] Recovery-коды показаны открытым текстом только один раз.
- [ ] В БД заполнены `totp_secret`, `totp_confirmed_at`, `totp_recovery_codes`.
- [ ] Секрет и recovery-коды не отображаются открытым текстом в БД или логах.
- [ ] Обновление страницы не показывает recovery-коды повторно.

Фактический результат / замечания:

>

## 4. TOTP challenge

- [ ] Завершить текущую сессию и войти как `admin` повторно.
- [ ] Переход в `/powerpuffsiteadmin` перенаправляет на `/cp/2fa/challenge`.
- [ ] Пустой код отклоняется валидацией.
- [ ] Код неправильной длины отклоняется.
- [ ] Неверный шестизначный код не даёт доступ в админку.
- [ ] Верный текущий TOTP-код открывает админку.
- [ ] Повторное открытие админки в пределах 30 минут не запрашивает код.
- [ ] Активность в админке продлевает 30-минутное окно.
- [ ] После 30 минут бездействия снова требуется challenge.
- [ ] Logout очищает авторизацию; после нового login снова требуется 2FA.

Фактический результат / замечания:

>

## 5. Rate limiting

- [ ] Отправить шесть неверных кодов в течение минуты.
- [ ] Следующая попытка получает `429 Too Many Requests`.
- [ ] Ограничение не раскрывает существование других пользователей или секреты.
- [ ] После окончания окна корректный код снова принимается.

Фактический результат / замечания:

>

## 6. Recovery-коды

- [ ] На challenge выбрать вход по recovery-коду.
- [ ] Первый неиспользованный recovery-код даёт доступ.
- [ ] Использованный recovery-код удаляется из сохранённого списка.
- [ ] Повторное использование того же кода отклоняется.
- [ ] Неверный recovery-код отклоняется.
- [ ] После использования последнего кода показывается предупреждение.
- [ ] Параллельные запросы с одним recovery-кодом не дают два успешных входа.

Фактический результат / замечания:

>

## 7. Отключение и повторная настройка

- [ ] Неверный TOTP-код не позволяет отключить 2FA.
- [ ] Верный TOTP-код отключает 2FA.
- [ ] После отключения очищены секрет, дата подтверждения и recovery-коды.
- [ ] После отключения `/powerpuffsiteadmin` снова ведёт на setup.
- [ ] Повторная настройка создаёт новый секрет.
- [ ] Старые TOTP- и recovery-коды больше не действуют.

Фактический результат / замечания:

>

## 8. Административный сброс

- [ ] Второй администратор может сбросить 2FA целевому администратору через UI.
- [ ] Действие записывается в журнал с инициатором и целевым пользователем.
- [ ] Команда `php artisan 2fa:reset admin@example.test` очищает 2FA.
- [ ] Команда для несуществующего email завершается безопасно и не изменяет других пользователей.
- [ ] После сброса старая 2FA-сессия целевого пользователя больше не должна давать доступ к админке.
